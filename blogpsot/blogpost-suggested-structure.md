GitHub Copilot SDK Challenge – Blog Post
There is no strict or required structure teams must follow. Patrick explicitly said teams can be creative in how they present their content. 
Reference blog post: Building an agentic memory system for GitHub Copilot - The GitHub Blog
Suggested structure:
1.	Title - Short, clear, and solution oriented – give your section a subtitle
2. Why We Built This - (Motivation / context — personal + practical)
•	What problem were you trying to solve?
•	What sparked the idea (hackathon, daily friction, curiosity)?
•	Who is this useful for?
3. What We Built - (High level overview — not too technical)
•	One paragraph description of the solution
•	What it does at a glance
•	Why it’s interesting or different
Aim for “middle tier” technical depth — clear, educational, not verbose. 
4. How It Works (At a High Level) - (Conceptual flow, not step by step code)
•	Architecture or process overview
•	Key components or building blocks
•	How GitHub Copilot SDK fits in
✅ Visual encouraged:
•	Architecture diagram (PowerPoint screenshot is fine)
•	Flow diagram
•	Annotated screenshot
Rough visuals are okay — GitHub design can polish later.  
5. What Makes This Powerful - (Highlight what’s worth learning from)
•	Interesting technical choices
•	Agentic behaviors, automation, or workflows
•	Tradeoffs, lessons learned, or insights
Patrick explicitly called out process flows and learning value. 
6. Demo & Artifacts
•	GitHub repo link, make sure it’s external ready
•	Demo video or recording, Screenshots or GIFs
